# 导入、导出、备份、恢复与遗忘

## 导入与检查点

网页支持 UTF-8 TXT、Markdown、JSON，单文件 2 MB。上传前显示文本预览、项目、分类、发言者、敏感级别与外部许可。JSON 校验语法后保留原始 JSON，不把任意结构字段直接提升为用户事实。

相同范围及相同原文 SHA-256 会返回 duplicate=true 并复用来源。写请求重试复用 Idempotency-Key；同键不同内容报 409。资料可以手动建立结构化记忆，或在生成模型配置后提炼候选。原文先持久保存，后台任务失败不会造成原文丢失。

每轮授权会话用稳定事件 ID 调用 ingest_event 或 HTTP checkpoint。明确标 speaker=user/assistant/quoted/unknown；混合聊天请按消息拆分，不能把助手输出视为用户事实。原文引用与字符位置一起保存，引用不在原文中时整批候选失败并可重试。

## 导出

网页“导出记忆”会分页下载完整授权范围内的结构化记忆。HTTP `/api/export` 返回 `next_offset`，可用 `examples/http_agent.py export` 获取全部页。Agent 导出受与检索相同的权限/有效时间限制，不包含其他项目或历史版本。

导出格式为 memory-hub-export-v1，供迁移、检查和归档。导出文件可作为 JSON 原始资料再次导入，但不会自动替换现有有效事实。需要完整还原版本、来源、配置时使用备份。

## 完整备份

网页下载的 memory-hub-backup-v1 包含来源全文、所有记忆和修订、项目、人格、关系、任务、策略、Agent 哈希和用户密码校验值。索引可重建，活动登录会话和完整 PAT 不备份。备份是敏感明文 JSON，下载后应立即加密；它不是去敏导出。

离线 CLI 备份建议停止写入服务，保证快照：

```sh
docker compose stop api worker
# 备份保存在持久卷，仅新建文件，不覆盖已有文件
docker compose run --rm --no-deps api python -m app.cli backup --file /data/backups/backup-2026-10-28.json
# 将文件导出到受保护目录后用组织认可的工具加密
# 同时保存独立的 /data/deletion-ledger.jsonl（存在时）
docker compose --profile public up -d
```

CLI 文件权限 0600。备份目录默认保留 30 天，可在设置修改；worker 会清理该目录过期 JSON。服务器外的下载、云盘和存储快照需自行清理，不受此策略控制。

## 恢复到当前服务器

网页恢复需要管理员、同所有者备份、确认替换；超过 8 MB 的备份使用 CLI。恢复事务会先保留现有删除标记，再导入备份，合并当前日志并清理已被遗忘的内容，最后重建词项索引和安排向量重建。全部 Agent 凭证撤销，全部登录会话失效，需重新登录并签发凭证。

离线恢复：停止 api/worker，将备份与**最新删除日志**放入受保护的数据卷，再运行：

```sh
docker compose run --rm --no-deps api python -m app.cli restore --file /data/backups/backup-2026-10-28.json
docker compose --profile public up -d
```

恢复会替换业务数据，先做一次当前备份。不能在正在写入的生产服务旁运行 CLI 恢复。保留的正文镜像从数据库重新生成，不能拿旧 sources 目录覆盖新目录。

## 迁移到新服务器

在新服务器准备空数据库、运行迁移，但不要先初始化另一所有者。把备份放入 `/data/backups`，把旧服务器**最新** `deletion-ledger.jsonl` 放在新数据卷 `/data/` 下，再使用 CLI restore。备份中的管理员密码继续有效；所有旧 Agent 凭证均已撤销，重新签发。

删除日志需要先合并而不是覆盖丢弃；一行是一条 UUID/哈希删除标记，不含正文。若日志损坏，服务拒绝启动/恢复，不会悄悄忽略。没有最新日志，无法保证未知旧备份中的已遗忘内容不会复活。

## 彻底遗忘

1. 打开记忆详情，预览整个来源依赖范围。共用来源或经过合并的派生内容也可能受影响。
2. 确认具体记忆 ID 集合；范围变化返回 409，需重新预览。
3. 选择整份删除来源或整份脱敏来源。清理相应记忆、修订、索引、任务、幂等结果和追踪关联。
4. 独立删除日志持久保留。对应原文哈希与记忆内容哈希禁止重新导入；后台与恢复路径继续应用标记。
5. 根据策略清理旧备份及外部副本。系统无法撤回已发送给外部 Agent 或已经进入旧对话的文字。

归档、回收站、彻底遗忘是不同操作。归档/回收站可恢复，彻底遗忘不可从本产品正常恢复；即使恢复旧备份，仍应被删除日志清理。
