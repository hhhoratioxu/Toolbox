# HoriPet architecture

The Electron main process owns all durable state and desktop behavior. Renderer windows receive immutable snapshots through a narrow preload bridge; they cannot read files, execute Node code or choose IPC channels. Settings writes are validated, bounded and applied immediately. The pet renderer renders a single SVG and compositor animations. The settings renderer is created on demand and destroyed on close.

`PetMachine` has exactly one state and one deadline. Drag has highest priority, then direct interactions, then cursor following, then random autonomous decisions. Feeding a sleeping pet first enters Wake. A user-requested nap persists until an explicit wake/interaction; autonomous naps have finite deadlines. No animation timers in React compete with main-process decisions. CSS animations select from the authoritative state class. Profiles and palettes make additional cats straightforward; a different species should introduce a renderer and a matching hit silhouette together.

The native pet window is compact, frameless, transparent and non-focusable. No screen-sized overlay is created. Screen coordinates are Electron device-independent pixels, including negative monitor origins; never multiply by display scale factors. Dragging reads the global cursor in the main process, avoiding accumulated errors when the native window moves. Positions are clamped to a connected work area, on changes to size, restore, display removal, resolution/scale changes and wake. Crossing a gap between displays snaps to a valid area. The entire visible window must fit a normal supported work area.

Mouse event forwarding is deliberately insufficient as a recovery mechanism: `setIgnoreMouseEvents(true, {forward:true})` does not forward clicks. A 100 ms main-process cursor poll tests a conservative SVG silhouette and restores input over the cat independently of renderer mouse events. Active motion uses a 33 ms timer; deep inactivity uses 300 ms; hidden pets use 1 second. The mask is an approximation: whiskers, animated edge pixels and bubbles remain noninteractive. A fast cursor may need up to one polling interval to re-enter. Actual behavior must be checked on each desktop OS, not inferred from a DOM click test. A twenty-second drag safety timeout and the native tray provide recovery if a pointer release is lost.

Autonomous motion is paused while a native menu is open. Cursor following activates within 650 DIP and expires after 6.5 seconds of no cursor movement. System inactivity after two minutes reduces scheduling and CSS update rates. The settings window preview uses the same SVG and state; there are no animation assets fetched from the network. Saving occurs after changes, at most every five seconds during movement, once per minute for care values, and synchronously on normal quit. Recovery tries the primary JSON then its previous valid backup.

The macOS adapter handles all workspaces/fullscreen spaces, Mission Control exclusion, Dock visibility and login items. Windows keeps the pet off the taskbar while preferences can appear as a regular window. Windows login uses the installed executable path and explicit empty arguments. Portable builds and development runs cannot register startup. Native startup settings are queried on launch instead of assuming a saved toggle reflects operating-system approval.

Production sessions block HTTP(S), WebSocket, permission grants, navigation and child windows. Only the configured local Vite origin is permitted in development. IPC requires a known window, its main frame, the application URL and a bounded request rate. No renderer method accepts a filesystem path, credential, arbitrary URL or arbitrary channel. All app features remain available offline. The optional AI contract lives entirely under `main/ai`; no AI provider is active in this preview. Future network access must be deliberately scoped for a configured main-process provider rather than relaxing renderer permissions.

The app holds a single-instance lock. Closing preferences destroys only that window. Quit cancels timers, flushes the latest state, destroys the tray and lets Electron terminate child processes. A renderer crash reloads that renderer; repeated startup failures are surfaced on stderr. Tests use an explicit `HORIPET_PROFILE` directory override without shipping an elevated debug API.
